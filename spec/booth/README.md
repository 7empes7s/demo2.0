# Booth board format and vectors, v1

What an independent verifier needs to replay a Booth board and confirm its tally, and what
`vectors.json` contains. `modules/booth` (Rust) is the only implementation; the vectors are
generated by it.

> `vectors.json` is **generated by this code from a public seed**. It shows that the
> implementation agrees with itself over time (drift test `modules/booth/tests/vectors.rs`),
> not that it interoperates with anyone. A second implementation that verifies the board in it
> and fails every must-fail case for the recorded reason is the interoperability evidence the
> Phase 3 criterion asks for. The protocol is **unaudited** and for non-binding rounds only.

All hex is lowercase. Byte lengths are exact and enforced before decoding. Points are
ristretto255, compressed, 32 bytes; the identity point is refused wherever a point is read.
Scalars are 32 bytes little-endian and must be canonical (less than the group order).

## 1. Primitives

| Piece | Standard / reference | Here |
|---|---|---|
| Group | ristretto255 (RFC 9496) | `G` = the ristretto basepoint |
| Encryption | exponential ElGamal | `(a, b) = (r·G, r·K + m·G)` |
| Proofs | Chaum-Pedersen, disjunctive Chaum-Pedersen, Schnorr; Fiat-Shamir over merlin transcripts | section 4 |
| Transcript | merlin 3 (STROBE-128, `Merlin v1.0`) | `Transcript::new(b"d2.booth/1")` |
| Key generation | joint Feldman VSS (Pedersen 1991) | section 3.2 |
| Signatures | Ed25519 (RFC 8032), small-order public keys refused | section 3.5 |
| Hash | SHA-256 | board chain, ballot digest |

merlin semantics, for implementers without the library: `Transcript::new(label)` is
`Strobe-128.new("Merlin v1.0")` then `append_message("dom-sep", label)`;
`append_message(label, data)` is `meta-AD(label)`, `meta-AD(LE32(len(data)), more=true)`, then
`AD(data)`; `append_u64(label, n)` is `append_message(label, LE64(n))`;
`challenge_bytes(label, 64)` is `meta-AD(label)`, `meta-AD(LE32(64), more=true)`, then
`PRF(64)`. A challenge scalar is those 64 bytes reduced modulo the group order
(`from_bytes_mod_order_wide`).

## 2. Board

```json
{ "schema": "d2.booth.board/1",
  "entries": [ { "seq": 0, "prev": "<64 hex>", "kind": "round.params", "payload": { ... }, "hash": "<64 hex>" }, ... ] }
```

- `seq` runs from 0 without gaps. `prev` of entry 0 is 32 zero bytes; otherwise the previous
  entry's `hash`.
- `hash = SHA-256("d2.booth.entry/1" || 0x00 || BE64(seq) || prev (32 bytes) || kind (ASCII) || 0x00 || canonical(payload))`.
- **Canonical JSON**: object keys sorted by byte value, no whitespace, numbers are integers
  only (no floats, no exponent), strings escaped as serde_json does (`"` → `\"`, `\` → `\\`,
  U+0008/9/A/C/D → `\b \t \n \f \r`, other control characters → `\u00XX` lowercase hex, everything
  else raw UTF-8). Payloads contain only strings, unsigned integers, arrays and objects.
- Unknown fields anywhere in an entry or payload make the board invalid.
- Any invalid entry makes the whole board invalid. A verifier never skips an entry.

### Entry order (state machine)

```
round.params                       exactly once, seq 0
guardian.commitment × n            guardian 1, 2, ..., n in order
round.key                          once
signup | ballot                    any number, any mix
round.close                        once
partial.decryption                 at least k, each guardian at most once
tally                              once, last
```

Ids (`round_id`, `nym`) are 1 to 128 characters of `[A-Za-z0-9._:-]`.

## 3. Payloads

### 3.1 `round.params`

```json
{ "schema": "d2.booth.round/1", "round_id": "booth:test-round-1", "matter_id": "matter:test",
  "options": ["yes", "no", "abstain"], "guardians": 3, "threshold": 2 }
```

2 to 64 options (labels 1 to 256 bytes), `1 <= threshold (k) <= guardians (n) <= 64`,
`matter_id` 1 to 256 bytes.

### 3.2 `guardian.commitment`

```json
{ "guardian": 1, "commitments": ["<C_0>", "<C_1>", ...], "proof": { "commit": "<A>", "response": "<v>" } }
```

Exactly `k` commitments `C_l = a_l·G` of guardian `i`'s polynomial `f_i(x) = Σ a_l x^l`.
The proof is Schnorr for `C_0`: transcript `T("guardian")` (section 4.0), then
`append_u64("guardian", i)`, `append_point("constant", C_0)`, `append_point("commit", A)`,
`c = challenge("challenge")`; check `v·G == A + c·C_0`.

Shares `f_i(j)` travel privately and are not on the board. Guardian `j`'s verification key is
derivable: `K_j = Σ_i Σ_l j^l·C_{i,l}`.

### 3.3 `round.key`

```json
{ "joint_key": "<K>", "guardian_keys": ["<K_1>", ..., "<K_n>"] }
```

Must equal `K = Σ_i C_{i,0}` and the `K_j` above, computed from the commitments. A verifier
recomputes and compares; it never trusts this entry.

### 3.4 `signup`

```json
{ "nym": "nym-a", "voter_key": "<32 bytes hex, Ed25519 public key>" }
```

One per pseudonym; a second is `duplicate_signup`. The pseudonym is Door's for the context
`booth:<round_id>` (the Door presentation itself is not on the board in v1).

### 3.5 `ballot`

```json
{ "round_id": "booth:test-round-1", "nym": "nym-a", "voter_key": "<as signed up>",
  "choices": [ { "a": "<r_0·G>", "b": "<r_0·K + m_0·G>" }, ... one per option ... ],
  "bit_proofs": [ { "commit_0_1": "..", "commit_0_2": "..", "commit_1_1": "..", "commit_1_2": "..",
                    "challenge_0": "..", "response_0": "..", "response_1": ".." }, ... one per option ... ],
  "sum_proof": { "commit_1": "..", "commit_2": "..", "response": ".." },
  "signature": "<64 bytes hex>" }
```

Checks, in order:

1. `round_id` equals the round's; `nym` has signed up and `voter_key` is exactly the key of
   that sign-up (otherwise `not_signed_up`); `choices` and `bit_proofs` have one element per
   option.
2. Signature: `digest = SHA-256("d2.booth.ballot/1" || 0x00 || canonical(ballot with "signature": ""))`;
   Ed25519-verify `(voter_key, digest, signature)`.
3. For every option `j`, the bit proof (section 4.2) over `(a_j, b_j)`.
4. The sum proof (section 4.3): with `A = Σ_j a_j`, `B = Σ_j b_j`, Chaum-Pedersen that
   `(A, B − G) = R·(G, K)`.

Only the **last** valid ballot of a pseudonym counts. Every ballot of a round has the same
shape and size.

### 3.6 `round.close`

`{}`

### 3.7 `partial.decryption`

```json
{ "guardian": 1, "shares": [ { "m": "<M_0>", "proof": { "commit_1": "..", "commit_2": "..", "response": ".." } }, ... one per option ... ] }
```

With the aggregates `A_j = Σ a_j`, `B_j = Σ b_j` over the counted ballots (last per
pseudonym), guardian `i` publishes `M_{i,j} = x_i·A_j` and proves it (section 4.4) against
`K_i` from the commitments. Guardian index in `1..=n`, at most once. If no ballot counted, the
aggregates are the identity and the round has no tally.

### 3.8 `tally`

```json
{ "signups": 6, "counted": 6, "counts": [3, 1, 2], "guardians_used": [1, 3] }
```

Checks: `counts` has one entry per option and sums to `counted`; `signups` and `counted`
equal the board's sign-up count and the number of pseudonyms with a valid ballot;
`guardians_used` is ascending, distinct, has at least `k` members, each with a partial
decryption on the board. Then for every option `j`, with Lagrange coefficients at zero over the
set `S = guardians_used`, `λ_i = Π_{m∈S, m≠i} m / (m − i)`:

```
D_j = Σ_{i∈S} λ_i · M_{i,j}          (equals x·A_j)
B_j − D_j == counts_j · G            else tally_mismatch
```

## 4. Transcripts and proofs

### 4.0 Start

Every proof's transcript starts `T(kind) = Transcript::new("d2.booth/1")`,
`append_message("kind", kind)`, `append_message("round_id", round_id)`. `append_point` is
`append_message(label, 32-byte compressed point)`.

### 4.1 Chaum-Pedersen (`ChaumPedersen`)

Statement: `(P, Q) = x·(G_1, G_2)`. Prover: `w` random, `commit_1 = w·G_1`,
`commit_2 = w·G_2`; append `commit_1`, `commit_2` (those labels); `c = challenge("challenge")`;
`response = w + c·x`. Verify: `response·G_1 == commit_1 + c·P` and
`response·G_2 == commit_2 + c·Q`.

### 4.2 Bit proof (0 or 1)

Transcript `T("bit")`, then `append_message("nym", nym)`, `append_u64("option", j)`,
`append_point("joint_key", K)`, `append_point("a", a)`, `append_point("b", b)`, then the four
commitments under `commit_0_1`, `commit_0_2`, `commit_1_1`, `commit_1_2`;
`c = challenge("challenge")`; `challenge_1 = c − challenge_0`. Verify all four:

```
response_0·G == commit_0_1 + challenge_0·a
response_0·K == commit_0_2 + challenge_0·b
response_1·G == commit_1_1 + challenge_1·a
response_1·K == commit_1_2 + challenge_1·(b − G)
```

### 4.3 Sum proof

Transcript `T("sum")`, `append_message("nym", nym)`, `append_point("joint_key", K)`,
`append_point("a_sum", A)`, `append_point("b_sum", B)`, then Chaum-Pedersen (4.1) with
`(G_1, G_2) = (G, K)` and `(P, Q) = (A, B − G)`.

### 4.4 Decryption share proof

Transcript `T("decrypt")`, `append_u64("guardian", i)`, `append_u64("option", j)`,
`append_point("guardian_key", K_i)`, `append_point("aggregate", A_j)`,
`append_point("share", M_{i,j})`, then Chaum-Pedersen with `(G_1, G_2) = (G, A_j)` and
`(P, Q) = (K_i, M_{i,j})`.

## 5. Error codes

A verifier reports one of: `chain_broken`, `malformed` (shape, hex, charset, unknown field,
derived key mismatch, tally bookkeeping), `params`, `out_of_order`, `proof_failed`,
`bad_signature`, `duplicate_signup`, `not_signed_up`, `below_threshold`, `tally_mismatch`,
`no_tally`. The must-fail vectors name the code each mutation must produce; where two checks
could both fail, the order in section 3 decides.

## 6. `vectors.json`

```
schema         "d2.booth.vectors/1"
generated_by   crate and version
seed           32 bytes hex (ChaCha20 seed; public test material, never for a real round)
primitives     the table above, as text
script         round id, options, n, k, each voter's choices in order (a second choice is a re-vote), decrypting guardians
board          the full published board (24 entries: params, 3 guardians, key, 6 sign-ups, 9 ballots, close, 2 partials, tally)
tally          what verify must return: {"signups":6,"counted":6,"counts":[3,1,2],"guardians_used":[1,3]}
must_fail[]    name, note, mutation, error
```

A mutation is one of:

- `{"op":"set","seq":S,"pointer":"/payload/...","value":V,"rehash":B}`: set the JSON pointer
  inside entry `S` (relative to the entry; a missing last key is inserted). With `rehash`
  true, recompute `hash` of entry `S` and `prev`/`hash` of every later entry (an operator
  rewriting history); with false, leave hashes alone (the chain must catch it).
- `{"op":"remove","seq":S}`: drop entry `S`, renumber and rehash the rest.
- `{"op":"truncate","len":N}`: keep the first `N` entries.
- `{"op":"duplicate","seq":S}`: insert a copy of entry `S` after it, renumber and rehash.

An independent verifier passes when it returns the recorded tally for `board` and the
recorded error code for every mutated board. Regenerate with
`cargo run -p d2-booth -- vectors --out spec/booth/vectors.json`; check with
`cargo run -p d2-booth -- check spec/booth/vectors.json`.
